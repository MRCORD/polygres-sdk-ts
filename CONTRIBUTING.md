## Development Environment

The SDK requires **Node.js 18+** with native `fetch` support.

1. **Clone the repository**:
   ```bash
   git clone https://github.com/MRCORD/polygres-sdk-ts.git
   cd polygres-sdk-ts
   ```

2. **Install dependencies**:
   ```bash
   npm install
   ```

3. **Verify the environment**:
   ```bash
   npm run typecheck && npm test
   ```

## Project Architecture

```
polygres-sdk-ts/
├── src/
│   ├── client.ts              # Core Polygres client, Project, Graph/Vector/Text/Hybrid namespaces
│   ├── context.ts             # ContextNamespace (pgContext 0.2.0 alignment & query plan builders)
│   ├── context-models.ts      # TypeScript interfaces and enums for pgContext contracts
│   ├── context-validation.ts  # Identifier, UUID, collection, and query validation utilities
│   ├── context-wait.ts        # Stage-aware operation polling and wait loop
│   ├── errors.ts              # Typed PolygresError hierarchy and automatic secret redaction
│   ├── errors-catalog.ts      # Canonical error catalog (688 mapped codes and safe detail fields)
│   ├── models.ts              # Response models (Page<T>, VectorResult, HybridResult, etc.)
│   ├── rows.ts                # RowsNamespace (validated mutations & pgContext reconciliation)
│   ├── version.ts             # Version constants and header names
│   ├── version-notices.ts     # Semantic version notice parser and central endpoint checker
│   └── index.ts               # Public package exports
├── tests/
│   ├── client.test.ts         # Client construction, options, and header tests
│   ├── context.test.ts        # pgContext search, limits, query builders, and wait polling tests
│   ├── errors.test.ts         # Error hierarchy, canonical resolution, and secret scrubbing tests
│   ├── namespaces.test.ts     # Graph, Vector, Text, and Hybrid namespace payload tests
│   ├── pagination.test.ts     # Page<T> async iteration (for await) and pagination tests
│   ├── retry.test.ts          # Retry loop, Retry-After header, and deadline tests
│   └── rows.test.ts           # Row validation, mutations, and context reconciliation tests
├── examples/                  # Runnable reference implementations (Cloudflare, Next.js, Node)
└── dist/                      # Dual ESM, CJS, and .d.ts build artifacts (generated by tsup)
```

## Core Design Principles

1. **Zero External Runtime Dependencies**:
   The SDK must have **zero runtime dependencies** in `package.json`. All networking, streaming, encoding, and crypto operations rely strictly on WHATWG / Web standard APIs (`fetch`, `AbortController`, `Headers`, `Response`, `TextEncoder`, `crypto.randomUUID()`, and `URL`). This guarantees seamless operation in Node.js (18+), Cloudflare Workers, Deno, Bun, and browser runtimes.

2. **Parity with Python SDK & pgContext**:
   Every capability, error code, validation rule, retry policy, and payload structure must remain in exact 1:1 parity with the reference Python SDK (`polygres-sdk`) and `pgcontext` specifications.

3. **Dual Naming Conventions**:
   Every method, property, and constructor parameter supports both idiomatic JavaScript `camelCase` (e.g. `apiKey`, `runtimeUrl`, `maxRetries`, `similarTo`) and Python-aligned `snake_case` (e.g. `api_key`, `runtime_url`, `max_retries`, `similar_to`).

4. **Safety & Secret Scrubbing**:
   Never log raw API keys (`poly_live_...`). All exception formats must pass through `redactText` and `redactValue`.

## Writing Tests

We use **Vitest** for testing.

- Place test files in `tests/` with the `.test.ts` extension.
- Mock HTTP responses using native `Response` objects passed to `new Polygres({ fetch: mockFetch })`.
- Never execute real network calls against external live endpoints in unit tests.
- When testing error responses, verify both the exception class (`err instanceof PolygresNotFoundError`) and canonical properties (`err.code`, `err.statusCode`, `err.details`).

Run tests in watch mode during development:
```bash
npx vitest
```

## Pull Request Process

Before submitting a PR, verify all gates pass locally:

```bash
npm run typecheck
npm run build
npm test
```

1. Create a feature branch from `main`:
   ```bash
   git checkout -b feature/my-improvement
   ```
2. Commit with conventional commit messages (`feat:`, `fix:`, `docs:`, `test:`, `refactor:`).
3. Open a pull request against the `main` branch.
4. Ensure GitHub Actions CI passes across all Node versions (18.x, 20.x, 22.x).
